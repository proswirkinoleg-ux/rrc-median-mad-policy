# Median + MAD Request Policy

Стратегия адаптивного таймаута и повторных попыток для лабораторной работы **Reliable Remote Calls** на C# / .NET 8.

Файл реализации: [MedianMadRequestPolicy.cs](MedianMadRequestPolicy.cs).
Исходный учебный симулятор: [k-shpak-bsu/RRCPublic](https://github.com/k-shpak-bsu/RRCPublic).

## Как работает

- Начальный таймаут — 120 мс. История содержит последние 64 результата попыток.
- После каждых 16 результатов таймаут пересчитывается. При наличии хотя бы 8 успехов статистическая оценка равна `median + 3 * MAD + 10 мс`; иначе используется текущий таймаут.
- Если доля таймаутов в истории больше 10%, ожидание увеличивается на 25%. Если при этом среди последних 16 результатов не меньше 12 таймаутов, ожидание увеличивается вдвое.
- При доле таймаутов не больше 2% ожидание пробует уменьшиться на 5%. Итог не ниже статистической оценки, но ограничен диапазоном 50–2000 мс.
- Повтор разрешён только после таймаута первой попытки. Пауза — 100 мс; при наличии 16 результатов и хотя бы 8 таймаутов среди последних 16 — 300 мс.
- Если в истории накопилось 16 таймаутов с ожиданием не меньше 1800 мс, включается ограничение повторов: первый подходящий повтор разрешается, следующие три пропускаются, затем цикл повторяется.
- Когда число таких длительных таймаутов в истории становится не больше 8, ограничение выключается.

Таймаут не считается точной длительностью ответа и не включается в расчёт медианы и MAD. Ограничение повторов — эвристика против дополнительной нагрузки, а не достоверное определение перегрузки.

## Подключение к симулятору

Этот репозиторий содержит файл стратегии, а не отдельное консольное приложение. Для сборки нужен `RRC.Abstractions` из учебного проекта.

1. Откройте проект [RRCPublic](https://github.com/k-shpak-bsu/RRCPublic).
2. Добавьте `MedianMadRequestPolicy.cs` в `RRC.Student`.
3. В `RRC.Runner/Program.cs` выберите стратегию:

```csharp
RRC.Abstractions.IRequestPolicy requestPolicy = new MedianMadRequestPolicy();
```

4. Из корня учебного проекта выполните:

```shell
dotnet build RRC.Runner/RRC.Runner.csproj -c Release
dotnet run --project RRC.Runner/RRC.Runner.csproj -c Release --no-build -- --seed 42 --trace 0
```

Для оценки по условиям лабораторной передаётся файл стратегии.

## Проверка

При переносе проверенного экспериментального варианта в этот упрощённый класс:

- Совпали 7 784 430 сравнений таймаутов и решений о повторе.
- Совпали итоговые метрики 720 проверочных прогонов: 660 основных и 60 с длительной перегрузкой.
- Проверены границы ожидания, включение и выключение ограничения повторов и восстановление после замедления.
- Проект `RRC.Runner` собран без ошибок и предупреждений.

Публичный сценарий при `seed = 42`:

```text
Success rate:       100.0 %
Mean latency:       99.96 ms
p95 latency:        145.21 ms
Attempts/request:  1.003
```

Это результаты локальных проверок, а не закрытых сценариев преподавателя. Тестовый стенд не включён в этот репозиторий. Стратегия не гарантирует устойчивость при постоянной нагрузке выше возможностей сервера; средняя задержка и p95 в симуляторе учитывают только успешные запросы.
